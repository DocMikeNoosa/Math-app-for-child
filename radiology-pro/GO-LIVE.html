Putting RadVox Pro online at radvox.pl

Step-by-step instructions for the person setting up the server. One server on AWS in Frankfurt runs both the website and the RadVox Pro application. radvox.eu and radvox.ai redirect to radvox.pl. Expect about 1.5–2 hours, plus waiting for DNS.

Main addresshttps://radvox.pl
Redirectswww.radvox.pl, radvox.eu, radvox.ai (+ www)

Rules for the helper The owner (Dr Mól) creates every account with their own email and card, and only the owner holds the passwords, the Anthropic API key and the backup key. The owner types or pastes secrets personally, or uses a password manager the owner controls. Secrets are never sent by email, chat or text message. No real patient data goes into the system until stage 11 is complete.

02Create the server in Frankfurt

Helper (owner logged in)
  1. Open lightsail.aws.amazon.com → Create instance.
  2. Location: Frankfurt, Zone A (eu-central-1a). This keeps stored data in the EU.
  3. Platform Linux/Unix → Blueprint OS Only → Ubuntu 24.04 LTS.
  4. Plan: the 4 GB RAM plan (2 vCPU). Name it radvox-pro → Create instance. Wait until it says Running.

03Point the domains at the server

Helper (owner logged in to the registrars)

Each domain needs two A records pointing to the static IP. Set TTL 300 (5 minutes) while setting up.

DomainRecordNameValue
radvox.pl (OVH)A@ (empty)static IP
radvox.pl (OVH)Awwwstatic IP
radvox.euA@ and wwwstatic IP
radvox.aiA@ and wwwstatic IP

OVH (radvox.pl)

  1. OVH Manager → Web Cloud → Domain names → radvox.pl → DNS zone.
  2. Edit the existing A records for the root (empty name) and www, and set them to the static IP. Don't add second copies next to them.
  3. Delete any AAAA records (IPv6) for the root and www. OVH's default zone often has them pointing to OVH's parking page, which blocks the HTTPS certificate.
  4. If www is a CNAME pointing to the root, that's fine too.
Watch outOVH's account is on the Canadian manager site (manager.ca.ovhcloud.com). The steps are the same. radvox.eu and radvox.ai weren't in that OVH account, so find where they were bought first.

04Install RadVox Pro (one command)

Helper, with the owner typing the secrets
  1. In Lightsail, open the instance → Connect using SSH. A terminal opens in the browser.
  2. Paste this one line and press Enter:
curl -fsSL https://raw.githubusercontent.com/DocMikeNoosa/Math-app-for-child/claude/polish-radiology-dictation-e0ov8p/radiology-pro/deploy/install.sh | sudo bash

The installer asks five questions (in Polish). Answer them like this:

QuestionAnswer
Główna domenatype radvox.pl (the suggested default is radvox.ai, so don't just press Enter)
Pozostałe domenytype radvox.eu radvox.ai (www versions are added automatically)
Twój e-mailthe owner's email. It's the admin login and receives certificate notices.
Hasło administratora (×2)owner types it: at least 10 characters, a letter and a digit, no spaces, quotes, # or $
Klucz API Anthropicowner pastes the key from stage 1 (starts with sk-ant-)
Klucz z resend.compress Enter for now (stage 7)

The installer then:

  • secures the server (firewall, automatic security updates, fail2ban);
  • installs Docker;
  • downloads RadVox Pro to /opt/radvox-pro;
  • writes the settings file;
  • starts the app.

It takes 5–10 minutes. At the end it prints the login address and a BACKUP_KEY.

Save the BACKUP_KEY nowThe owner stores the BACKUP_KEY in the owner's password manager. Without it, the encrypted backups can't be opened.
If a domain wasn't pointing at the server yetThat's fine. The installer warns and carries on, and HTTPS switches on by itself once DNS reaches the server.

07Email (password resets, invitations)

Helper (owner creates the account)

Without email the app works, but password-reset links and invitations only appear in the admin panel. The app uses Resend.

  1. Create a Resend account (owner's email) → Domains → Add domain radvox.pl. Choose an EU region if one is offered.
  2. Add the DNS records Resend shows (TXT for SPF/DKIM, possibly MX for a subdomain) in the OVH DNS zone, then click Verify.
  3. API Keys → create a key (sending access). On the server, the owner puts it in the settings file:
sudo nano /opt/radvox-pro/radiology-pro/deploy/.env
# set:  RESEND_API_KEY=re_...      (save: Ctrl+O, Enter; exit: Ctrl+X)
cd /opt/radvox-pro/radiology-pro/deploy && sudo docker compose up -d

08Backups: a copy outside the server

Helper

The app already backs up both databases every day, encrypted with the BACKUP_KEY, and keeps 14 days on the server. Lightsail snapshots add a daily image of the whole machine. One more copy must live outside this server, in the EU:

  1. Create EU object storage with S3 access (e.g. OVHcloud Object Storage, Scaleway or Backblaze B2 in an EU region), in the owner's name.
  2. On the server: sudo apt-get install -y rclone, then sudo rclone config → new remote named exactly offsite (type S3, keys from the storage provider).
  3. Test once, then schedule it nightly:
cd /opt/radvox-pro/radiology-pro/deploy && sudo bash offsite-backup.sh
sudo crontab -e
# add this line:
30 3 * * * /opt/radvox-pro/radiology-pro/deploy/offsite-backup.sh >> /var/log/radvoxpro-offsite.log 2>&1

10Make the code private, keep updates working

Helper (owner logged in to GitHub)

The repository is public so the installer could download it. After installing:

  1. GitHub → repository → Settings → Change visibility → Private.
  2. Create a fine-grained personal access token with access to this one repository only: Contents: Read-only, with an expiry date the owner chooses.
  3. On the server, let updates use the token (the owner pastes it):
sudo git -C /opt/radvox-pro remote set-url origin https://x-access-token:PASTE_TOKEN_HERE@github.com/DocMikeNoosa/Math-app-for-child.git
sudo radvox-update

From then on, installing a new version is one command: sudo radvox-update. Do it at a quiet hour; it causes a short pause, and reports in progress are retried automatically.
